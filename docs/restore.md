# 找回以前的数据库版本

误删、误改或遇到云盘冲突后，可以下载服务保存的历史版本，用自己的密码管理器检查并恢复。

本指南不会要求提供主密码。解锁和条目比较都在你自己的密码管理器中完成。

## 开始之前

1. 暂停在其他设备上编辑这个数据库，避免旧副本再次覆盖主库。
2. 将当前主库和所有冲突副本分别另存一份。暂时保留云盘回收站中的文件。
3. 确认要恢复谁的数据库，以及他的历史放在哪个目录。

默认示例目录为 `KDBX-Backups/me`，哥哥的为 `KDBX-Backups/brother`。实际位置以对应 `config.json` 的 `targets` 为准。

## 1. 选择一个历史版本

在 Google Drive 或坚果云网页中打开备份文件夹。选择出问题之前的版本，下载：

- 以 `vault_` 开头的 `.kdbx` 文件。
- 与它同名的 `.kdbx.sha256` 文件。

文件名中的时间是 UTC。例如 `20261109T120000...Z` 表示 2026 年 11 月 9 日 12:00 UTC，即北京时间当天 20:00。

如果云盘中的版本不完整，也可以到服务器的 `KDBX_BACKUP_DATA_ROOT/实例名/snapshots/` 查找。这里的 `KDBX_BACKUP_DATA_ROOT` 代表 `.env` 配置的实际目录。

## 2. 检查下载是否完整

把数据库和对应校验文件放在同一文件夹。以下提供两种方法，任选一种。

### 使用项目管理工具

在项目文件夹输入 `python3 scripts/manage.py verify `，末尾保留一个空格，再把下载的 `.kdbx` 文件拖入终端，按回车执行。Windows 使用 `python`。

**确认结果：** 显示 `OK:` 和文件名。工具会在同一位置查找对应的 `.sha256`。

### 使用 Mac 的校验命令

在终端进入下载文件夹，运行：

```sh
shasum -a 256 -c *.kdbx.sha256
```

**确认结果：** 选中的文件显示 `OK`。校验失败时重新下载，或尝试另一个备份目标，不要直接恢复校验失败的文件。

## 3. 作为另一份数据库打开

在 StrongBox、KeePass 或 KeePassXC 中打开下载的副本，使用自己的主密码和密钥文件解锁。

检查以下内容：

- 最近添加或修改的重要账号。
- Passkey、验证码密钥、自定义字段和附件。
- 需要保留的条目历史。
- 与当前主库有差异的条目。

**确认结果：** 你能正常解锁，并确认它包含准备恢复的内容。能打开、条目数量相同或文件更大，都不能单独证明它是所需的最新完整版本。

如果两个副本各有新内容，先使用密码管理器的比较或合并功能检查差异；不要仅按文件大小选择。

## 4. 恢复到日常主库位置

1. 确认当前文件和冲突副本已经另存。
2. 关闭各设备正在编辑的数据库。
3. 使用主库云盘的网页或客户端，将选定版本放回日常使用的文件路径。
4. 等待云盘完成上传。
5. 在每台设备上重新打开当前主库，确认关键条目和自动填充使用的数据库正确。

如果保持原文件名和路径，备份服务会继续检查这个路径；更换了名字或文件夹，需要修改 `source` 并重启任务。

## 5. 确认恢复后的版本已备份

按[状态检查步骤](operations.md)查看任务。恢复内容与上一份快照不同，会新增一份历史；完全相同时会跳过。等待所有目标的 `pending` 为 `0`。

保留旧历史，直到确认各设备都在使用正确主库。服务不会自动把备份恢复到主库，也不自动解决客户端之间的冲突。
